# 记忆体（dsh-memory）

DSH 插件。把 DSH 的会话按天存档，入口在**设置**里。

## 装

```powershell
.\install.ps1
```

装完重启 DSH。设置页左侧会出现「记忆体」。

撤销：

```powershell
.\install.ps1 -Uninstall
```

## 里面有什么

| 控件 | 作用 |
|---|---|
| DSH 开关 | 关掉就完全不跑 DSH 那一半 |
| 全部工作区 | 勾上备份所有工作区；不勾就只备份勾选的那几个 |
| 存档目录 | 产出放哪儿 |
| 脚本目录 | 留空 = 用插件包里自带的那份脚本。填了就用那个目录里的 |
| 关于我 | 只读：内容和最后修改时间 |
| 启动时读取关于我 | 把原文写进勾选工作区的 `AGENTS.md`，只对新开的对话生效 |
| 输入框的「读关于我」 | 点一下填一句话进输入框。一个对话每天一次就够 |
| 自动备份 | 开关 + 时间。到点自己跑，一天只跑一次 |
| 立即备份 | 先存设置，再跑 |

## 边界

- 插件**不含**备份逻辑。真正的活是仓库根目录的 `backup-chat.ps1` 和
  `export-session.mjs` 干的。插件只负责界面、存设置、把参数拼好、把脚本叫起来。
- **自动备份只在 DSH 开着的时候有效。** 插件里跑的是进程内定时器，DSH 关了就没有了。
  到了点但 DSH 没开，下次开起来会补一次（当天只补一次）。要关机也能跑，得用系统的计划任务。
- 「上次自动」那行会记住哪天跑过、成没成，写在 settings.json 里。
- 所以「脚本目录」必须指向一份可用的仓库；改了路径要在这里同步。
- 设置存在 `$DSH_HOME/dsh-memory/settings.json`。
- 四个路由都过「回环 + 同源」检查，只有本机的界面能调。

## 文件

```
lib/index.js     Host 半：三个路由，扫工作区，调用脚本
lib/client.js    Client 半：设置页那一节
cordis.patch.yml bundle 层，把自己插进组装树
install.ps1      装 / 卸
```
